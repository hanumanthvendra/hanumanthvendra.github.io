RAG · runbooks · citations · refusal

Cite the runbook — or refuse. Never invent a kubectl.

Ask a raw LLM how to fix an alert and it answers confidently — sometimes with a flag that does not exist. This copilot embeds the question, cosine-ranks your runbooks, and only then generates. If the best hit is below MIN_SCORE 0.62, it says I won't guess. Retrieval is local (bge-small). Generation is a swap: mock offline, Claude when a key is set.

question embed retrieve cite & answer refuse

One sentence for interviews: retrieval decides whether you may speak; the LLM only phrases what the runbook already said.

The four hops (in order)

Nothing after step 4 invents knowledge. The gate is the product.

01 · Question

POST /ask

On-call types a paraphrase, not a runbook ID. “container restarting, exit 137, empty logs.”

02 · Embed

bge-small

Same model on ingest and query. Local CPU. No API key for retrieval.

03 · Retrieve

Cosine top-k

Rank passages from 7 runbooks + 3 postmortems. Return score + citation metadata.

04 · Gate

MIN_SCORE 0.62

Best hit below the dial → refuse. Above → expand the full top doc, then generate with citations.

Interview Q&A

Short answers you can say out loud.

Q · Walk me through a question

Embed the question with bge-small. Cosine-rank runbooks and postmortems. If the best score is under 0.62, return the refusal string and empty sources. If it is over, expand the entire top document (so Resolution is in context), send only that block to the LLM, and require citations like [RB-003 §Resolution].

Q · Why refuse instead of letting the model “help”?

In an incident, a plausible-but-wrong command is worse than no answer. The ungrounded mock invents kubectl repair — a flag that does not exist — to show that failure mode. Refusal is the feature.

Q · Where does the LLM sit?

After retrieval and the score gate. Mock by default (deterministic, CI-safe). Set ANTHROPIC_API_KEY and the same retrieved context goes to Claude. Retrieval never needs a frontier model.

Q · Why expand the whole top runbook, not just the chunk?

Retrieval often hits Diagnosis or Symptoms. The action lives in Resolution. Parent-doc expansion feeds the full runbook so grounding sees the fix, not only the matching paragraph.

Q · How is this different on Kubernetes?

Same gate. Store becomes Qdrant (PVC). Embeddings become a shared service so ingest and query cannot drift models. Copilot is a stateless API behind an HPA. Ingest is a Job (CronJob in production).

Q · Citations vs correctness?

A citation is traceability. If RB-003 was last verified three Kubernetes versions ago, the copilot still retrieves it but warns stale and tells you to re-validate. /metrics counts which docs fire and how often a stale doc was top hit — that is the docs backlog.

Q · How do you eval it?

Paraphrased questions in eval/questions.yaml — not copied keywords. Measure retrieval hit@k and refusal accuracy. Grounded answers must be cited; hallucinated commands must be zero.

The product is the gate: retrieve from your runbooks, cite the passage, or refuse. The LLM only writes the sentence.
